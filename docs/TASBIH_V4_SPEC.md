# Тасбих v4: настраиваемая последовательность и новый рост

## A. Настраиваемая последовательность

Сейчас «Последовательность» — жёстко три первых поминания по 33 (`SEQUENCE`, `SEQUENCE_DHIKR`).
Делаем её настраиваемой.

Модель (`src/tasbih/model.js`):

- `state.sequence` — массив шагов `{ id, target }`. `id` — id из `DHIKR` или `custom:<id>` своего поминания.
  `target` — целое 1…999. Шагов 1…12.
- `DEFAULT_SEQUENCE = [{subhanallah,33},{alhamdulillah,33},{allahuakbar,33}]` (экспорт). Константы `SEQUENCE` и
  `SEQUENCE_DHIKR` убрать, все места перевести на функции ниже.
- `sequenceSteps(state)` → массив разрешённых определений шагов: то же, что `definition()` вернул бы для одиночного
  поминания (для своего — текст, арабский, перевод), но с `target` шага. Шаг, который не разрешился, пропускается;
  если не осталось ни одного — шаги `DEFAULT_SEQUENCE`.
- `definition(state)` в режиме `sequence` → `steps[currentDhikrIndex]` (индекс по модулю длины). `circleLimit` на
  последовательность не влияет, как и раньше.
- `advance` → индекс `(i + 1) % steps.length`.
- `tapEvent`: в режиме `sequence` при `next.currentDhikrCount === target шага` → `'complete'`, если это последний
  шаг (по `next.currentDhikrIndex` — registerDhikr уже продвинул индекс), иначе `'circle'`. Последовательность из
  одного шага — каждое завершение `'complete'`. Остальные режимы без изменений.
- `perDhikrCounts` копится по id поминания шага (`subhanallah`, `custom:c…`).
- `setSequence(state, steps)` — чистит вход: выбрасывает неизвестные id, `target` округляет и зажимает в 1…999,
  обрезает до 12 шагов; пустой результат → `DEFAULT_SEQUENCE`. Если результат не изменился — вернуть тот же state.
  Если выбран режим `sequence` и шаги изменились — `currentDhikrIndex = 0`, `currentDhikrCount = 0`.
- `removeCustomDhikr` убирает шаги с этим поминанием из `sequence` (пусто → `DEFAULT_SEQUENCE`; если режим
  `sequence` и шаги изменились — сброс индекса и счёта, как выше).
- `restoreState` чистит `sequence` тем же правилом (нет поля / мусор → `DEFAULT_SEQUENCE`); `sanitizeCounters`
  берёт индекс по модулю длины шагов, а не 3.

Интерфейс:

- `useTasbih` — метод `setSequence(steps)`.
- `DhikrSheet`: у строки «Последовательность» вторая строка — состав, например
  «Субханаллах 33 · Альхамдулиллях 33 · Аллаху акбар 34» (numberOfLines 2), справа кнопка «Настроить»
  (иконка `options`, 44×44, как кнопка удаления у своих поминаний). Она переключает шторку в редактор
  (внутреннее состояние шторки; заголовок шторки «Последовательность»/«Sequence»).
- Редактор — новый `src/tasbih/SequenceEditor.js`:
  - строки шагов: номер, название (numberOfLines 1), степпер `−` [число] `+` (число — TextInput
    `keyboardType="number-pad"`, правка применяется на blur/submit, зажим 1…999; `−`/`+` по одному),
    стрелки вверх/вниз (`up`/`down`, крайние неактивны), удалить (`close`, неактивно при одном шаге);
  - «Добавить поминание» раскрывает список (встроенные `DHIKR` + свои), выбор добавляет шаг с 33; при 12 шагах кнопки нет;
  - быстрые наборы-чипы: «33 · 33 · 33» и «33 · 33 · 34» (классика после намаза; Аллаху акбар 34);
  - «Готово» возвращает к списку режимов. Каждое изменение сразу уходит в `setSequence` (сохраняется).
  - Все кнопки ≥ 44×44, accessibilityLabel на русском/английском по `lang`, стили — из `theme` как в `DhikrSheet`.
- `TasbihScreen`: точки под счётчиком — по одной на шаг из `sequenceSteps(state)` (вместо `SEQUENCE_DHIKR`).

## B. Рост без сроков

Сейчас стадия требует и роста, и активных дней (`minimumDays` до 75), в сутки засчитывается не больше 100,
дерево растёт ~2,5 месяца, а зёрна (неделя, круг 99, плоды) приходят быстрее, чем их успеваешь вырастить.

Новые правила:

- Каждое поминание — 1 единица роста активному дереву; первые 33 за день — по 2 (награда за ежедневность).
  `GROWTH = { bonusTaps: 33, bonusMultiplier: 2 }`, `growthForCount(count) = count + min(count, 33) * (2 - 1)`;
  прирост на касание — разность, как сейчас. Никакого дневного потолка, никакого `activeDayContribution`.
- `STAGES` — только `requiredProgress`: `[0, 40, 160, 360, 640, 1000, 1450, 2000]`. Поле `minimumDays` убрать,
  `chooseStage(progress, stages = STAGES)`; `growthRatio(tree)` — только по росту.
  Темп: 99 поминаний в день → плоды примерно за 15 дней; 33 в день → около месяца; 300 в день → около недели.
- Зёрна. Три источника: плоды (`'harvest'`: активное дерево впервые доходит до плодоношения, порода по весам),
  каждый седьмой день зикра (`'week'`, `GIFT_EVERY_DAYS`) и первый подъём дерева до стадии 4 «Молодое дерево»
  (`'growth'`, `GIFT_STAGE`, по разу на дерево). Подарки `'week'` и `'growth'` несут только породу, которой у игрока
  ещё нет ни деревом, ни зерном (сидр — когда уже есть три породы); когда коллекция собрана, подарка нет.
  Зёрна за круг 99 (`'circle'`) убраны вместе с `lastCircleDropDate`. Старые `pendingDrops` с этими причинами по-прежнему показываются (SeedDrop не трогать).
  Если активное дерево уже плодоносит, но `harvested === false` (после миграции), зерно выдаётся на ближайшем
  касании.
- Рост не пропадает: пока активное дерево плодоносит, прирост копится в `state.reserve` (потолок
  `RESERVE_CAP = STAGES[5].requiredProgress`, т. е. 1000 — новое дерево стартует не дальше «Крепкого дерева»).
  `plantSeed` отдаёт весь запас новому дереву: `progress = reserve`, `stage = chooseStage(reserve)`,
  `reserve = 0`.
- Глобальные `activeDays`/`tree.activeDays` продолжают считаться (информативно), на стадии не влияют.
- Версия сохранения → 3. `restoreState` принимает 1, 2, 3. Из v2: `sequence` по умолчанию, `reserve = 0`,
  у каждого дерева `stage = max(stage, chooseStage(progress))` (старые прогрессы больше — деревья подрастут),
  `lastCircleDropDate` удалить. `reserve` чистится: конечное число ≥ 0, не больше `RESERVE_CAP`.

Интерфейс:

- `GardenSheet` — правила:
  - «Каждое поминание растит дерево, первые 33 за день — вдвое.» / «Every remembrance grows the tree; the first 33 each day count double.»
  - «Когда дерево приносит плоды — новое зерно.» / «A tree in fruit gives a new seed.»
  - «Рост после плодов не пропадает — он перейдёт к следующему посаженному зерну.» / «Growth after fruiting is kept for the next seed you plant.»
  - если `reserve > 0` — строка над зёрнами «Запас роста для нового дерева: N» / «Growth saved for the next tree: N» (N — целое).
  - пустое состояние зёрен: «Зерно выпадет, когда дерево принесёт плоды.» / «A seed drops when the tree bears fruit.»
- `TasbihScreen`, подвал: если активное дерево плодоносит и есть зёрна — под строкой породы короткая подсказка
  «Посадите зерно — рост перейдёт к нему» / «Plant a seed — growth carries over» (вместо полосы роста).
- README и docs/TASBIH.md — абзацы о росте и зёрнах привести к новым правилам.

## C. Дополнение: коллекция, роща, пятница, окно после намаза

- **Роща.** У дерева поле `inGrove`. `retireTree(state, id)` отправляет в рощу плодоносящее (`isFruiting`) дерево,
  которое не является активным; `plantSeed` уводит в рощу плодоносящее активное дерево, которое сменяет новое.
  `setActiveTree` не принимает дерево из рощи. Порода из рощи остаётся в коллекции (`ownedSpecies` смотрит на все деревья).
- **Пятничное зерно.** Первая за день завершённая последовательность (`tapEvent === 'complete'`) в пятницу даёт зерно
  (`reason: 'friday'`, поле `lastFridayGift` — дата последней выдачи). Порода — новая, а если все есть — по весам.
- **Окно после намаза.** `AFTER_PRAYER = { minutes: 30, multiplier: 1.5 }`; `registerDhikr(..., { afterPrayer })` умножает
  прирост. Окно берётся из `utils/prayerWindow.js`, куда экран намаза кладёт последние дни графика.
- **Коллекция и календарь.** «Сад» показывает «N из 5» (закрытые породы — бледным силуэтом); календарь главного экрана
  отмечает точкой дни с зикром (`dailyDhikrCounts`).
