# Noor

Мусульманское приложение для iPhone: время намаза, кибла, Коран, обучение арабскому чтению и ежедневное чтение.

Expo SDK 54 · React Native 0.81 · React 19 · iOS 18+, Liquid Glass на iOS 26.
Около 7 800 строк JavaScript и Swift. Данные хранятся на устройстве, аккаунта нет.

---

## Разделы

Навигация — четыре вкладки внизу экрана, панель в стиле Liquid Glass.

| Вкладка | Экран | Что внутри |
|---|---|---|
| **Намаз** | `PrayerTimesScreen` | Кольцо обратного отсчёта, фаза луны, две даты, расписание на день, вход в тасбих |
| **Кибла** | `QiblaScreen` | Компас с направлением на Каабу |
| **Коран** | `QuranScreen` → `SurahReaderScreen` | Суры, перевод, пословный разбор, чтецы |
| **Чтение** | `ReadingScreen` | Ежедневная цель, серия, аят дня |

Обучение арабскому чтению (`LearnScreen`, `CoursePathScreen`, `LessonPlayerScreen`) — курс из 14 юнитов: от первых букв через огласовки и слоги к словам.

## Время намаза

### Главный экран

- **Кольцо** отмеряет промежуток между предыдущим и следующим намазом.
- **Луна** внутри кольца освещена ровно на ту долю, что сегодня на небе. При открытии экрана набирается за 1,4 секунды.
- **Две даты** — григорианская и по хиджре. Нажатие открывает календарь.
- **Расписание** свёрнуто в спойлер и в свёрнутом виде показывает намаз через один: ближайший уже стоит в кольце.
- Строки расписания лежат прямо на обоях, без плиток; читаемость держит тень под текстом.

### Источники расчёта

| Источник | Как считается |
|---|---|
| **Авто: ДУМ вашего региона** (по умолчанию) | Официальный график духовного управления места (`officialTables.js`, встроенный или с сервера); на дату таблицы нет — запасной способ управления; управления нет — метод страны (`countryMethods.js`). Подробнее ниже |
| **Кавказ (ДУМ КБР)** | На устройстве. В Кабардино-Балкарии — официальный график ДУМ (`officialTables.js`; серверные таблицы КБР, например на 2027, он видит так же), вне его дат и вне республики — `dumCalc.js`, метод, восстановленный из графиков |
| Лига исламского мира, Турция, Египет, Умм аль-Кура, Карачи, ISNA | Aladhan API; без сети — локально через `adhan` |
| Офлайн | На устройстве, `adhan` |

#### Авто: ДУМ вашего региона

Новые установки начинают с этого источника; сохранённый выбор прежних пользователей не меняется. Решение принимает `planAuto` в `prayerSource.js`, один раз на все пути (с сетью, без сети, описание для настроек):

1. **Управление места** (`resolveAuthority`): по региону, если он известен; иначе по кругу `radiusKm` любого пункта; управление с пустым `regions` подходит всей своей стране. Региональное управление побеждает страновое.
2. **Таблица** ближайшего пункта за год даты. Нет таблицы этого года — та же дата прошлого (29 февраля берёт 28-е), ответ помечен `approximate`.
3. **Запасной способ управления**, когда таблицы на дату нет: формула ДУМ КБР (`dumKbr`) или метод Aladhan (`aladhan`) с мазхабом Асра из записи управления, а если он не назван — из настройки пользователя. Без сети метод Aladhan заменяет ближайший локальный метод `adhan`, и экран сообщает, что считает офлайн.
4. **Нет управления** (или запасной способ не знаком этой версии приложения) — метод по стране места.

Таблицы мазхаб Асра не учитывают: он уже в графике управления.

Метод по стране (`src/constants/countryMethods.js`): ISO-код → номер метода Aladhan, к нему ближайший локальный метод `adhan` по углам Фаджра и Иши (RU и KZ — 14 → ISNA, TR, AZ, DE — 13 → Турция, SA — 4, EG — 5, PK, IN, BD — 1 и т. д.). Страна не из списка — 3, Лига исламского мира. Страна места (`country`, ISO-2) берётся у геокодера при GPS и из поиска города.

Что именно сейчас стоит за «Авто», возвращает `describeAutoSource(where, date)`: режим (`table`, `previousYear`, `fallback`, `country`), год таблицы, управление, пункт и способ расчёта. Она нужна экрану настроек.

#### Метод ДУМ КБР

Ни одна библиотека его не воспроизводит: у ДУМ **угол ограничен по времени**, а библиотеки знают только «угол плюс постоянный сдвиг».

| Время | Правило |
|---|---|
| Фаджр | Угол 15°, но не позже чем за 90 минут до восхода |
| Восход | Астрономический |
| Зухр | Солнечный полдень + 10 мин |
| Аср | Шафиитский счёт (коэффициент тени 0,99) + 10 мин |
| Магриб | Закат + 2 мин |
| Иша | Угол 15,25°, зажатый между 103 и 112 минутами после заката |

Совпадение с официальным графиком на 91 дне (июнь, сентябрь, декабрь 2026):

| Время | В пределах минуты | Макс. ошибка |
|---|---|---|
| Восход, Зухр, Магриб | 91 / 91 | 1 мин |
| Фаджр | 88 / 91 | 2 мин |
| Иша | 81 / 91 | 3 мин |
| Аср | 62 / 91 | 3 мин |

Точнее формулой не выйдет: официальная таблица сглажена вручную. В октябре 2026 Аср по формуле позже графика на 1–3 минуты. Поэтому в приложение встроен сам график.

#### Официальный график

Таблицы — это графики, которые публикуют сами духовные управления. Их два источника, и работают они вместе:

- **Встроенные**: `assets/prayer-tables/`. `index.json` — снимок списка управлений (сейчас одно, ДУМ КБР), рядом сами таблицы (сейчас КБР на 1 октября – 31 декабря 2026). Новую таблицу мало положить в папку: нужна строка `require` в `BUILTIN_TABLES` и запись о её пункте в `index.json`, иначе Metro её не соберёт или она останется недостижимой. За этим следит тест.
- **С сервера** [noor-times](https://m65012487-wq.github.io/noor-times/v1/index.json): статические JSON на GitHub Pages, формат описан в `FORMAT.md` репозитория сервера. `timesServer.js` ставит их в `officialTables.js` через `installIndex` и `installTables`, а сохраняет в AsyncStorage под ключами `officialTables:v1:*`. Установленное заменяет встроенное: управление — по id, таблица — по тройке управление + пункт + год.

Формат файла таблицы и индекса описан в шапке `officialTables.js`. Приложение работает и без сервера: встроенные графики и скачанные раньше остаются.

Строка таблицы заменяет запасной способ, когда сходится всё:

- **Управление и пункт.** Выбранному по региону управлению (непустой `regions`, регион места содержит часть) достаётся ближайший пункт без ограничения радиусом: у ДУМ КБР один пункт на республику, а Терскол от него в 94 км. Управлению на всю страну (пустой `regions`, совпала страна места) — ближайший пункт, только если место не дальше его `radiusKm`: иначе таблицы нет и работает метод управления, а не время города за 300 км. Если неизвестны и регион, и страна, действует круг `radiusKm`: он запасной вариант и захватывает, например, и Пятигорск, и Назрань.
- **Пояс.** `utcOffset` таблицы равен поясу устройства в полдень этого дня. Пояс берётся из таблицы, у Казахстана это +05:00, у Сингапура +08:00.
- **Дата.** Таблица покрывает этот день; иначе берётся та же дата прошлогодней.

Регион, страна и версия графиков (`tablesVersion()`: отпечаток всех таблиц и свойств управлений) входят в ключ кэша дней, поэтому новая или исправленная таблица пересчитывает и сохранённые дни. Экраны следят за версией через `useTablesVersion()` и пересчитывают времена сразу, когда таблица пришла.

**Синхронизация** (`syncOfficialTables`): при смене места и источника и при возвращении приложения на передний план, только для «Авто» и «Кавказ (ДУМ КБР)». Не чаще раза в 12 часов, но без ожидания, если таблицы для нового места индекс уже обещает, а на устройстве их нет. Индекс запрашивается с `If-None-Match`; таблицы ближайшего пункта качаются за годы Y−1, Y, Y+1, если они есть в индексе и их `hash` отличается от сохранённого. Сеть, таймаут (15 с) и мусор в ответе возвращают `false`, но не ломают приложение. Сохранённое поднимает `loadStoredTables()` на старте, до первого расчёта.

**Ночные Фаджр и Иша.** В высоких широтах строка даты D иногда записывает Фаджр до полуночи (ДУМ РТ, Казань, май: 23:54) или Ишу после неё. По смыслу первый — вечер D−1, вторая — D+1. `prayerMoment(day, name)` в `calendarDate.js` ставит такое время на настоящие сутки: события, уведомления и окно будильника на Фаджр пользуются им. Признак: Фаджр позже восхода, Иша раньше магриба. Виджет на Swift время по-прежнему читает как часы строки даты.

> Aladhan с методом 14 «ДУМ РФ» для Кабардино-Балкарии неверен: на 7 сентября 2026 даёт Ишу 19:52 против официальных 20:16.

Официальные графики лежат картинками: `https://dinri-duneiri.ru/azan/2026009.jpg` — год и месяц с ведущим нулём.

### Календарь

Лист на месяц: числа григорианского календаря крупно, по хиджре мелко под ними, неделя с понедельника. Внизу — времена намаза на выбранный день и освещённость луны.

Хиджра считается **табличным (кувейтским) алгоритмом**, а не через `Intl`: в Hermes набор календарей неполон и молча отдаёт григорианскую дату. Месяц по хиджре начинают по наблюдению молодого месяца, поэтому таблица расходится на день-другой. Поправка — в настройках, по умолчанию −1 (сверено с ДУМ КБР на 7 сентября 2026).

### Уведомления

- В момент каждого намаза и восхода, плюс напоминание заранее — отдельным уведомлением.
- Звук напоминания и звук наступления времени выбираются **раздельно** из общего списка: системный, колокольчик, колокол, тихий. Каждый можно прослушать.
- Уровень **Time Sensitive** — пробивает режим сна и «Фокус».
- Расписание на 4 дня вперёд. iOS держит не больше 64 отложенных уведомлений, 12 мест оставлено будильнику.

**Азан в уведомлении звучать не может.** iOS пускает туда только несжатый файл из бандла не длиннее 30 секунд, а азаны — mp3 по сетевым ссылкам длиной в минуты. Азан проигрывается в приложении.

### Умный будильник на Фаджр

- Первые 6 звонков раз в минуту, дальше с выбранным интервалом, до восхода. Не больше 12.
- Собственный звук на 29 секунд (`alarm.wav`) — предел для звука уведомления.
- Открытие приложения или «Я проснулся» останавливает цепочку.

Боковой переключатель в бесшумном режиме глушит любой звук уведомления. Обойти это может только Critical Alerts — разрешение Apple, выдаётся по заявке при платном аккаунте разработчика.

## Кибла

Компас на `expo-location`: истинный курс, при недоступности — магнитный. Вращается только циферблат; стеклянный диск неподвижен, чтобы блик не крутился вместе со шкалой.

Буквы сторон света повёрнуты **по радиусу**, как на картушке компаса: при повороте телефона сторона, к которой повернулся, оказывается вверху ровно стоящей буквой.

## Коран

- Текст, перевод и пословный разбор **встроены** (`assets/quran`, 6,8 МБ) и работают без сети.
- Сеть нужна для аудио чтецов (`api.alquran.cloud`) и пословного разбора при первом открытии суры (`api.quran.com`).
- Закладки, место последнего чтения и масштаб шрифта хранятся на устройстве.
- Настройки чтения — отдельный лист: чтец, перевод, показ арабского, транслитерации и перевода, пословный режим, арабский шрифт.

## Тасбих

Счётчик зикра с деревом, которое растёт от поминаний. Вход — веточка без подписей: при открытии приложения (и после пяти минут в фоне) она выпадает из-за правого края экрана, качнувшись, и замирает над таб-баром, едва покачиваясь на ветру; её находят из любопытства. Веточка — тихий силуэт цвета темы, каждый раз другая (восемь веточек Krea-2: олива, инжир, виноград, миндаль, гранат, шелковица, сидр, лавр). Тёплая точка у кончика — есть зёрна для посадки.

### Счёт

- **Последовательность** — по умолчанию Субханаллах, Альхамдулиллях, Аллаху акбар по 33: круг из 99. Настраивается кнопкой справа от строки в шторке режима: от 1 до 12 шагов, любое поминание (встроенное или своё), у каждого шага своё число повторений от 1 до 999. Быстрые наборы «33 · 33 · 33» и «33 · 33 · 34» (классика после намаза: Аллаху акбар 34).
- **Одно поминание** из десяти: три основных и семь дополнительных (Ля иляха илляЛлах, Астагфируллах, Субханаллахи ва бихамдихи, Субханаллахиль-Азым, Ля хауля ва ля куввата илля билЛях, салават, Хасбуна-Ллаху ва ни‘маль-вакиль), **свободный зикр** без цели и **свои тексты**.
- Нажатие по дереву — одно поминание: дерево качнётся, и из места касания во все стороны разлетятся листья. Конец шага (по умолчанию круг из 33) отмечается сильной отдачей, вспышкой за счётчиком и поливом — лейка — силуэт цвета темы, как дерево, — у ствола поливает землю у корня.

### Дерево

8 стадий: Зерно, Росток, Побег, Саженец, Молодое дерево, Крепкое дерево, Взрослое дерево, Плодоносящее.

Дерево растёт только от поминаний, сроков нет: каждое поминание — единица роста, первые 33 за день считаются вдвое (награда за ежедневность), потолка в сутки нет. Стадию определяет один лишь накопленный рост, плоды — при 2000: 99 поминаний в день приведут к ним примерно за 15 дней, 33 в день — за месяц, 300 в день — за неделю. 5 пород — олива, инжир, гранат, финиковая пальма, сидр (редкий: выпадает, когда уже есть три породы).

Рисунок — плоский слоистый силуэт цветом схемы, как сцены на обоях. Кадры нарисовал Krea-2 в оттенках серого (`scripts/tasbih_assets/prompts_v5.py`), сборщик `build_v5.py` переводит тёмность в прозрачность и раскладывает их по холсту 240×300 с корнем в одной точке; цвет даёт тема через `tintColor`. Глубина — тоном: дальняя листва полупрозрачна, ствол и ближние ветви плотные. У каждой породы свой облик (кривой ствол оливы, лопастной инжир, многоствольный гранат, перистая пальма, зонтик сидра); зерно и росток общие.

### Сад

Зерно выпадает по одному за каждое выращенное дерево — в тот раз, когда активное дерево впервые дошло до плодов. Рост после плодов не пропадает: пока активное дерево плодоносит, он копится в запасе (не больше 1000, это «Крепкое дерево») и целиком переходит к следующему посаженному зерну. В «Саду» (значок листа в шапке) зерно сажают, видно запас роста, а любое дерево делают активным. Зёрна, выпавшие раньше за неделю или за круг 99, остаются и сажаются как обычно. Прогресс хранится только на устройстве.

## Оформление

Три независимые оси.

### Узор

| Род | Варианты | Как рисуется |
|---|---|---|
| Без узора | — | Градиент схемы |
| Плитки | Цветок, Гирих | Бесшовная плитка |
| Сцены | Пустыня, Караван, Кедры, Всадник, Цветение | Три плана с **параллаксом** при наклоне телефона. Новые сцены нарисовал Krea-2 в трёх тонах серого, `scripts/tasbih_assets/build_scenes_v5.py` раскладывает тон на планы |

Все картинки белые на прозрачном и красятся тоном схемы, поэтому одна картинка работает со всеми схемами.

Параллакс: дальний план сдвигается на 7 точек, ближний на 30. Опорный угол медленно подтягивается к текущему — сцена сама возвращается в центр, когда телефон замирает. Системное «Уменьшение движения» выключает эффект.

### Цветовая схема

20 вариантов: 10 глубоких (Тушь, Песок, Мох, Слива, Пепел, Море, Закат, Ночь, Олива, Ягода) и 10 светлых (Жемчуг, Лён, Шалфей, Сирень, Роза, Небо, Абрикос, Мята, Румянец, Лаванда). Светлоту ограничивает контраст приглушённого текста.

### Шрифт интерфейса

6 наборов, у каждого кириллица проверена по таблице `cmap` файла.

| Набор | Семейство | Откуда |
|---|---|---|
| Системный | SF Pro | iOS |
| Округлый | SF Pro Rounded | iOS |
| Гротеск | PT Sans | Встроен в `assets/fonts` |
| Широкий | Verdana | iOS |
| С засечками | Georgia | iOS |
| Книжный | PT Serif | Встроен в `assets/fonts` |

Шрифт без кириллицы ничего не ломает: iOS подменяет буквы системным шрифтом посимвольно, и настройка выглядит нерабочей. Поэтому Gill Sans, Avenir Next, Optima, Futura и Iowan Old Style исключены.

### Арабский шрифт

6 встроенных в iOS: Системный, Geeza Pro, Al Nile, Damascus, Mishafi, Baghdad.

## Виджет

WidgetKit через `@bacons/apple-targets`, код в `targets/widget`.

- **Домашний экран** — все времена на день, включая самый маленький квадратный виджет.
- **Экран блокировки** — три ближайших времени.

Виджет не считает времена сам: приложение публикует готовый срез дня в общую App Group (`widgetBridge.js`). Иначе на Swift появился бы второй источник правды, который однажды разошёлся бы с приложением.

### Шрифт по всему приложению

В React 19 `Text.defaultProps` не работает, поэтому все тексты идут через `AppText`. Он подмешивает выбранное семейство **под** переданный стиль. `fontFamily: 'System'` служит маркером арабского текста и заменяется выбранным арабским шрифтом.

### Генераторы ассетов

Картинки и звуки нарисованы и синтезированы кодом, внешних ассетов нет.

| Скрипт | Что делает |
|---|---|
| `scripts/patterns/build.js` | Бесшовные плитки: рисует поле 3×3 и вырезает центр — края гарантированно стыкуются |
| `scripts/scenes/build.js` | Сцены по три плана для параллакса |
| `scripts/icon/build.js` | Иконка, adaptive-иконка, заставка |
| `scripts/sounds/build.js` | Звуки уведомлений и будильника |
| `scripts/tasbih_assets/build_v5.py` | Силуэты деревьев (5 пород × 8 стадий) и лейки из кадров Krea-2 → `assets/tasbih/{trees5,can.png}`, `src/tasbih/{treeArt,canArt}.js`; `sheet` — лист выбора в цвете темы |

Генераторам картинок нужен `sharp` (деревьям тасбиха — нет). Он ставится без сохранения и между запусками пропадает:

```bash
npm install sharp --no-save
```

## Сборка

### Проверка на Windows

Mac нет, поэтому iOS-проект локально не компилируется, но JS проверяется полностью:

```bash
npx eslint src/ App.js
```

```bash
npx expo export --platform ios
```

Второе прогоняет весь Metro: выход 0 означает, что бандл собирается.

### .ipa

GitHub Actions, `.github/workflows/unsigned-ipa.yml`, раннер `macos-15`. Нативного проекта в репозитории нет — его разворачивает `expo prebuild` на раннере.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `include_widget` | `true` | Собирать с виджетом |
| `bundle_id` | `app.noor.mobile` | Bundle ID |

```bash
gh workflow run unsigned-ipa.yml
```

Сборка неподписанная, подпись — через eSign на самом iPhone, сертификат в CI не попадает.

**Bundle ID обязан отличаться от других приложений на устройстве**: одинаковый iOS считает обновлением и затирает соседнее приложение вместе с данными.

### Конфигурация `app.json`

- `expo-notifications` — звуки уведомлений: `chime`, `bell`, `soft`, `alarm`.
- `expo-font` — PT Sans и PT Serif, регистрируются на сборке.
- `expo-splash-screen` — заставка.
- `ios.entitlements` — App Group для виджета и `time-sensitive` для уведомлений.

## Известные ограничения

| Что | Почему |
|---|---|
| Азан не звучит в уведомлении | Нужен несжатый файл ≤ 30 с из бандла; азаны — mp3 по сети |
| Будильник молчит в бесшумном режиме | Обойти может только Critical Alerts от Apple |
| ДУМ КБР вне графика — до ±3 минут | Встроенный график кончается 31.12.2026. Дальше и за пределами КБР считает формула, а сам график сглажен вручную |
| Хиджра может разойтись на день | Месяц начинают по наблюдению; есть поправка в настройках |
| Метод ДУМ подогнан под Нальчик | Дагестан, Чечня и другие ведут свои графики — проверять отдельно |
| `time-sensitive` может не пережить переподпись | Тогда уведомления не пробьют «Фокус»; остальное работает |
